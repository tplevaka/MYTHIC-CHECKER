# MYTHIC CHECKER 1.4.0 — запуск на Linux

## Совместимость и статус проверки

Готовый архив MYTHIC-Checker-v1.4.0-linux-x64.tar.gz содержит Electron/Node: отдельно устанавливать Node.js для него не нужно.
Это сборка для настольного Linux x86_64 с glibc и графической сессией X11/Wayland, например актуальных Ubuntu, Debian, Fedora, Arch и SteamOS в Desktop Mode. Это НЕ гарантия работы на любой версии Linux: ARM, 32-битные системы, Alpine/musl, очень старые библиотеки и сервер без графического окружения этим архивом не поддерживаются.

Сборка подготовлена на Windows. Архив и ELF-исполняемый файл проверены; Linux-источники XDG, Steam, /proc и journalctl протестированы на изолированных искусственных данных. Запуск в настоящей Linux-сессии на этой машине не тестировался: WSL и Docker отсутствуют. Windows-сборка и запуск включённых Windows-утилит протестированы отдельно.

## Запуск готовой сборки

Откройте терминал в папке, куда скачали архив:

```bash
tar -xzf MYTHIC-Checker-v1.4.0-linux-x64.tar.gz
cd MYTHIC-Checker-v1.4.0
chmod +x mythic-checker chrome_crashpad_handler chrome-sandbox
./mythic-checker
```

Приложение запускайте от обычного пользователя, чей ПК и аккаунты проверяются. Не запускайте весь интерфейс через sudo: это изменит домашнюю папку и может скрыть Steam/браузерные записи нужного пользователя.

Если Wayland не запускает окно, попробуйте установленный XWayland:

```bash
./mythic-checker --ozone-platform=x11
```

Если система сообщает об отсутствующей библиотеке, установите зависимости через штатный менеджер пакетов. Не скачивайте случайные DLL/SO из Интернета.

Ubuntu 24.04+/Debian с пакетами t64:

```bash
sudo apt update
sudo apt install libgtk-3-0t64 libnss3 libxss1 libgbm1 libasound2t64 libatk-bridge2.0-0t64 libdrm2
```

На Ubuntu 22.04/Debian без t64 используйте обычные имена libgtk-3-0, libasound2 и libatk-bridge2.0-0 вместо соответствующих t64-пакетов.

Fedora:

```bash
sudo dnf install gtk3 nss libXScrnSaver mesa-libgbm alsa-lib atk at-spi2-atk libdrm
```

Arch:

```bash
sudo pacman -S gtk3 nss libxss mesa alsa-lib at-spi2-core libdrm
```

Для дополнительных источников нужны usbutils (lsusb), pciutils (lspci), iproute2, procps и, на systemd-дистрибутивах, journalctl. Отсутствующая команда должна рассматриваться как недоступный источник, не как доказательство чистого ПК.

При ошибке Chromium sandbox не отключайте защиту параметром --no-sandbox и не выключайте AppArmor/антивирус. Используйте поддерживаемую конфигурацию пользовательских пространств имён вашего дистрибутива либо соберите и установите штатный DEB на Linux; при корпоративной политике обратитесь к администратору. Портативный архив сам не изменяет системные разрешения и не устанавливает привилегированный sandbox.

## Что работает и что отличается от Windows

- Поиск файлов: имена, пути, небольшие скрипты; корневое сканирование не обходит /proc, /sys, /dev и /run.
- Steam: стандартная установка, .steam/root, Flatpak и Snap, доступные записи loginusers.vdf/config.vdf/userdata. Для нестандартной установки откройте STEAM Accounts → Select Steam folder и выберите корень Steam, содержащий config и userdata. Выбор дополняет автоматическое обнаружение.
- Недоступные каталоги другого пользователя не обходятся и не открываются с повышением прав. Стёртые локальные аккаунты восстановить нельзя.
- Recent files: встроенное окно с данными XDG recently-used.xbel. Некоторые приложения/окружения не ведут эту базу; отсутствие базы явно сообщается.
- Process monitor (Linux): все доступные процессы, пути, модули работающего CS2 через /proc/PID/maps и LD_PRELOAD. Steam overlay и другие нестандартные библиотеки сами по себе не доказывают инъекцию. Доступ к памяти чужих процессов может быть запрещён.
- Trace / Anti-evasion: автоматически открывается и проверяется при запуске. Показывает совпадения сохранённых запусков/удалений, команды очистки в доступной истории и проверку доступного systemd journal. Сигналы, предупреждения и недоступные проверки отображаются отдельно; Show list раскрывает исходные записи.
- Windows Defender, BAM/DAM, Prefetch, реестр Windows и NTFS USN не существуют в нативном Linux и не имитируются. PC Registry на Linux проверяет переменные окружения и системные журналы.
- System Informer и RecentFilesView — Windows-программы. В Linux используются явно обозначенные встроенные аналоги; остальные Windows-only карточки отключены, а не отправляют на сайты Windows-программ.
- История браузеров проверяется только там, где имеются читаемые поддерживаемые источники. Совпадение домена не доказывает установку читов. Очистка истории, закрытый доступ и ограничения размеров могут скрывать записи.

## VAC, игровые баны и CS2

VAC отображается у каждого найденного аккаунта отдельно от игровых банов. Публичные данные загружаются через Steam Community; нужен Интернет. При недоступных данных будет Unknown, а не автоматически «нет бана».

Для официального GetPlayerBans задайте СВОЙ Steam Web API key перед запуском. Ключ не включён в установщик, исходники или экспортируемый отчёт. Не публикуйте ключ на сайте и не пересылайте его вместе с архивами.

Linux — ввод без отображения ключа и без записи самого ключа в команду:

```bash
read -r -s -p 'Steam Web API key: ' MYTHIC_STEAM_API_KEY
export MYTHIC_STEAM_API_KEY
./mythic-checker
unset MYTHIC_STEAM_API_KEY
```

Windows — в PowerShell задайте переменную MYTHIC_STEAM_API_KEY в том же процессе/окружении, из которого запускаете установленный MYTHIC CHECKER. Путь к EXE зависит от выбранного каталога установки.

Важное ограничение Steam: число VAC/game bans само по себе не определяет, в какой игре был бан. Если API возвращает запись bans с диапазоном AppIdMin/AppIdMax, включающим App 730, чекер показывает подтверждённый бан CS2 и доступный BanStartTime в UTC. Если такой записи нет, а имеются глобальные баны, статус конкретной игры остаётся неизвестным. Наличие ключа не гарантирует выдачу детальной записи для каждого аккаунта.

DaysSinceLastBan переводится только в ПРИБЛИЗИТЕЛЬНУЮ дату последнего бана в любой игре. Это не точное время выдачи VAC и не доказательство бана именно в CS2. Эти данные намеренно не выдумываются.

## Сборка из исходников на Linux

Установите Node.js LTS 22/24, npm, git и инструменты сборки вашего дистрибутива. Распакуйте архив исходников и откройте терминал в mythic-checker:

```bash
npm ci
npm run typecheck
npm run build
npm run dist:linux
```

Сборка AppImage/DEB должна выполняться на Linux. Файлы будут в release17 (build.directories.output в package.json). Для AppImage может понадобиться FUSE 2 из менеджера пакетов; для DEB используйте штатную установку пакета вашей системой. Эта инструкция не означает, что AppImage/DEB уже протестированы на каждой системе.

Разработка:

```bash
npm run dev
```

Для ARM потребуется отдельная поддерживаемая Electron-сборка нужной архитектуры и независимая проверка; приложенный x64-архив её не заменяет.

## Распространение

Windows-установщик включает неизменённый RecentFilesView 1.33 с полным исходным комплектом NirSoft и System Informer 4.0.26241.138 с оригинальными лицензиями/уведомлениями. RecentFilesView разрешено распространять только бесплатно и без изменения полного комплекта. Не удаляйте его readme.txt/CHM. System Informer распространяется с оригинальными MIT/сторонними уведомлениями. Эти Windows-программы не включены в Linux-архив.

Установщик MYTHIC не подписан вашим сертификатом издателя: Windows может показать предупреждение SmartScreen. Защита Windows Defender не отключается, исключения не добавляются; раздел Trace читает уже существующие настройки, не меняя их.
